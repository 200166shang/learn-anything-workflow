# Video Learning 本地中文配音优化验证

测试机器：16GB Apple Silicon Mac（M5），测试输入为约 30 秒英文讲话。

## 结论

当前机器的最佳可用质量档是 **Qwen3-TTS 0.6B Base 8-bit 音色克隆 + MLX 级联**。1.7B 8-bit 虽然理论上质量更高，但本机压力测试在 328 秒内仍未生成首段，峰值 memory footprint 达 17.27GB，系统已发生明显交换空间扩张，不适合纳入日常流水线。

## 实测

| 配置 | 结果 | 速度 | 内存 | 判断 |
|---|---:|---:|---:|---|
| SeamlessM4T v2 Large 直接音频翻译 | 30 秒输入生成 24.38 秒中文 | 推理 44.48 秒 | RSS 约 5.84GB；footprint 约 7.9GB | 声音和译文都有明显错误 |
| Qwen3-TTS 0.6B Base 8-bit 克隆 | 两段共约 23.4 秒中文 | 生成 15.37 秒；RTF 0.64/0.67 | MLX 峰值 5.79GB；进程 footprint 约 12.5GB | 当前推荐 |
| Qwen3-TTS 1.7B Base 8-bit 克隆 | 328 秒未产出首段，人工终止 | 不可用 | footprint 17.27GB；交换占用增加约 2GB | 16GB 本机不推荐 |

0.6B 使用固定随机种子 42、temperature 0.5。反向 ASR 显示主体内容完整，但段首仍偶发音近错词。因此“更高质量”不能只靠增大模型，应靠自动验收与局部重试。

## 推荐流水线

1. `yt-dlp` 只下载一次音频，统一转成 16kHz mono WAV。
2. MLX Whisper Large-v3 Turbo 转写，并保留时间戳和说话人分段。
3. 4-bit 中文翻译模型按语义句群翻译；专名、数字和术语进入强制词表。
4. 从每位说话人选取 10–20 秒干净参考音频，使用 Qwen3-TTS 0.6B Base 8-bit 克隆。
5. 每段控制在约 40–70 个中文字；固定 seed，temperature 约 0.5。
6. TTS 后用轻量 ASR 回听，比较数字、专名、术语、漏句和重复。失败段最多再生成两次，只替换失败段。
7. 合并音频并按原时间线做有限速率调整，避免强行压缩导致口齿异常。

## 性能策略

- ASR、翻译、TTS 串行驻留，不同时加载三个模型；阶段结束后释放模型和 MLX cache。
- TTS 模型在整个节目内常驻，避免每段重复约 8 秒的加载成本。
- TTS 并发固定为 1。可以让 CPU 同时做文本校验或音频封装，但不要并发跑第二个生成模型。
- 默认只生成一个候选；仅对自动验收失败的片段重试。相比全量双候选，通常能以小幅额外耗时换取明显稳定性。
- 启动前检查 memory pressure。若系统已处于黄色/红色压力或大量 swap 活跃，先暂停，而不是启动 1.7B。

## 建议质量档

- `balanced`：0.6B、单候选、仅关键术语检查。
- `high`（默认推荐）：0.6B、固定参数、完整回听校验、失败段最多重试两次。
- `max`：不建议在 16GB 本机使用 1.7B；可在 24GB/32GB Apple Silicon 或远端机器上启用，并保留相同验收流程。
