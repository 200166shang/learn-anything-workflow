# Learning

Confirm the user's learning goal, material scope, and registered source version. Create a module only after that confirmation. A new conversation or newly discovered material is not permission to create another module.

Use `video-extract learning recommend --module-id MODULE --workspace CONFIG --json` to prepare root-question recommendations. Explain how a small set of candidates connects the confirmed scope, then wait for the user to choose. Recommendations are temporary and must not be entered as history.

Save the chosen root immediately with `learning thread create`. Save every actual follow-up immediately with `learning pursue`, even before an answer exists. Do not merge questions by title. Use the relationship that reflects the actual entry (`deepens`, `applies`, or `related`). When the user returns to a known question, always pass both `--existing-question-id QUESTION_ID --actual-question "THE USER'S WORDS THIS TIME"`; the identity and original question remain unchanged while this entry preserves what they actually asked and its return route. Never omit or synthesize `--actual-question` from the historical question. If identity is ambiguous, show the returned choices; only use `--independent` after the user confirms it is a separate question. Never persist an unselected recommendation.

Run `explanation prepare` for the selected question and follow its model action. Preserve the returned stable section marker. Distinguish course facts, current code, supplemental sources, and inference in the evidence JSON. Commit only via `explanation commit`; never overwrite result objects or learning snapshot files directly.

Before reusing an explanation from another module, inspect its exact question and locator and write a `--reuse-review` JSON object naming `target_question_id`, `concept`, `semantic_equivalence`, `coordinate_assumptions`, non-empty `applicability_conditions`, `citation_intent`, and the `local_context` that must remain understandable in the current root. Do not reuse by title alone. `explanation prepare` verifies the target's pinned sources and records the exact target module/thread/question/explanation revision/section/object digest; `explanation commit` rejects a draft that omits the reviewed local context. For a multi-question refactor, set `local_question_id` when the reference belongs to another mapped question; changed section text or marker order requires a recheck bound to that exact local question/reference, while a byte-equivalent section block may remain untouched as a child section changes. A later `learning locate` reports a moved or changed target as `needs_review`; rerun the explicit applicability review before revising the current root. Never edit the target root, copy its feedback, or broadcast a rewrite to unrelated roots.

Register public supplemental material with complete provenance and applicability, then add it with role `supplemental_source`. Treat `manual_review_required` as an external-fact review boundary. Before reuse, honor `learning module show` and `learning locate` source checks: keep historical explanation locations visible, revise only `needs_review` claims, and do not silently move a pinned reference to a new source version. Current-code locators use exactly `file::symbol`/`symbol` or `file:start-end`/`line_range` plus the file content digest; bare files are invalid. An inference never becomes a course or code fact.

Choose the teaching profile that matches the material: `linear_transform`, `recognition_to_action`, or `frame_pipeline`. The final explanation must support the profile's causal and boundary checks, not merely contain a fixed summary template. If a required source version is unavailable, pause that question and leave unrelated questions usable.

After an explanation, ask only when useful whether the user explicitly understands, remains confused, or wants to park it. Persist that answer with `learning feedback`, including the user's original words and a concrete `--confusion` when supplied. Silence, a correct answer, browsing, and practice results are not understanding feedback.

Use `learning resume --module-id ...` (or `--thread-id ...` when already known) first when a user says “continue learning.” It is read-only and returns the saved thread, question, feedback, confusions, and route. If the question is parked, present its `continue` and `back` choices and wait; do not choose a branch. An explicit same-root or cross-root continuation uses `learning resume --thread-id TARGET --question-id ... --from-question-id ...`; return with `learning back`. `learning show`, `learning locate`, and cross-root references are read-only and must never be used as position switches.

Pass the last observed `expected_revision` on feedback and position changes. A stale change to the same question or position becomes a preserved candidate for the user to resolve; an unrelated question feedback may be safely revalidated and merged by the tool. A preserved pursue candidate contains the normalized complete intent and may be applied only after the user chooses it, via `learning replay --candidate ...`; never reconstruct a partial command from conversation memory. Never edit learning snapshot files directly.
